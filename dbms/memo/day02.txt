PRIMARY KEKY(PK) (기본키)
   - 고유한 값
   - 각 행의 구분점으로 이용된다.
   - PRIMARY KEY는 테이블당 오직 하나의 필드에만 설정할 수 있습니다.
   - 이 제약 조건이 설정된 필드는 NULL 값을 가질 수 없으며, 또한 중복된 값을 가져서도 안 됩니다.
    
FOREIGN KEY (FK) (외래키)
   - 외래키는 두 테이블을 서로 연결하는 데 사용되는 키이다.
   외래키가 포함된 테이블을 자식 테이블이라고 하고 외래키 값을 제공하는 테이블을 부모 테이블이라한다.
   - 중복이 가능하다

모델링의 개념 
   - 현실 세계의 비즈니스 프로세스와 데이터 요구 사항을 추상적이고
   구조화된 형태로 표현화는 과정
   - 데이터 베이스의 구조와 관계를 정의하며, 이를 통해 데이터의 저장, 조작, 관리 방법을 정의

데이터 모델링의 3단계
   1) 개념적 설계, ER(Entity-Relationship)
   - 업무 개념을 시각적으로 표현하고, 개체 간의 관계와 속성을 정의
   
   2) 논리적 설계
   - 개념적 모델의 개체(Entity)를 테이블(Table)로 변환하고, 
   관계(Relationship)를 외래키(Foreign Key)로 표현
   
   3) 물리적 설계
   - 논리적 모델을 기반으로 실제 데이터베이스 시스템에 구현
   
즉, 추상적인 설계의 레벨은 아래와 같다
   - 개념 -> 논리 -> 물리
   
모델링의 특징
   1) 단순화(Simplifictation)
      - 현실을 단순화하여 핵심 요소에 집중
      - 단순화를 통해 복잡한 현실 세계를 이해하고 표현

   2) 추상화(Abstraction)
      - 현실세계를 일정한 형식으로 맞추어 간략하게 표현

   3) 명확화(Clarity)
      - 대상의 애매모호함을 명확하게 표현한다. (구체화)

데이터의 모델링 관점
   1) 데이터 관점(ERD)
      - 데이터가 어떻게 저장되고, 접근되고, 관리되는지 정의
      
   2) 프로세스 관점
      - 시스템이 어떤 작업을 수행하며, 이러한 작업들이 어떻게 조작되는가
   
   3) 데이터 프로세스 관점
      - 데이터 관점 + 프로세스 관점
      - 데이터를 어떻게 사용하는지, 어떻게 생성되는지를 정의

데이터 모델링(설계)시 유의 사항
   1) 중복
      - 한 테이블은 여러 테이블에 같은 정보를 저장하지 않는다   
   2) 비유연성
      - 컬럼의 추가 또는 데이터 추가의 유연성을 갖는다. 단, 잦은 모델링 변경이 되지 않도 록 주의
   3) 비일관성
      - 데이터베이스 내의 정보가 모순되지 않고 관계를 명확히 정의해야 한다.
      - 학번의 데이터가 다른 테이블에도 있지만 서로 다른 경우
      - ex) A 테이블 학번 0001, B 테이블 학번 A0001
      
데이터 모델링
   - 대상(Thing)
   - 속성(Attribute)
   - 관계(Relation)
   

스키마
   - 데이터베이스의 구조와 제약 조건에 관한 전반적인 명세를 기술한 데이터베이스의 집합
   - 데이터를 관리하는 파일의 포괄적인 단위
   
   1) 외부 스키마
   - 사용자 관점으로 데이터베이스 스키마를 정의
   - 사용자 관점으로 "이런 데이터가 필요할 거야", 즉 테이블이 반드시 필요하지 않다.
   
   2) 개념 스키마
   - 사용자 관점을 통합하여 테이블의 구조 정의
   - "그렇다면 이렇게 테이블을 만들자!", 즉 반드시 테이블이 필요하다
   
   3) 내부 스키마
   - 테이블에 데이터가 어떻게 들어갈 것인가를 정의
   - "이 테이블을 이렇게 저장하자!", 구조, 컬럼, 인덱스 등등이 필요하다.
   
ERD(Entity Relationship Diagram)
   - 논리적 설계 단계에서 테이블과 테이블간의 관계를 시각적으로 표현한 것
   - 데이터 모델링의 표준
   
PostgreSQL 데이터 타입 정리

1. 정수형 (Integer)
   - SMALLINT    : 작은 정수 (2 bytes)
   - INTEGER    : 기본 정수 (4 bytes)
   - **BIGINT   : 큰 정수 (8 bytes)

2. 실수 / 소수 (Floating / Numeric)
   - REAL              : 4바이트 부동소수점
   - DOUBLE PRECISION  : 8바이트 부동소수점
   - NUMERIC(p, s)     : 정확한 소수 (금액 처리용)
   - **NUMERIC: 실수랑 정수 둘 다 가능

3. 문자열 (String)
   - CHAR(n)      : 고정 길이
   - VARCHAR(n)   : 가변 길이 (최대 제한 있음)
   - **TEXT         : 가변 길이 (제한 없음) - 실무에서 많이 사용

4. 날짜 / 시간 (Date & Time)
   - **DATE           : 날짜 (YYYY-MM-DD)
   - TIME           : 시간 (HH:MM:SS)
   - TIMESTAMP      : 날짜 + 시간
   - **TIMESTAMPTZ    : 시간 + timezone 포함 (실무 추천)

5. 불리언 (Boolean)
   - BOOLEAN : TRUE / FALSE / NULL

6. 자동 증가 (Auto Increment)
   - **GENERATED AS IDENTITY : 표준 SQL 방식 (권장)

7. UUID
   - UUID : 전역 고유 식별자 타입

8. JSON
   - **JSONB : 바이너리 JSON

9. 배열 (Array)
   - **INTEGER[]
   - **TEXT[]


제약조건
   - 제약조건(constraint)이란 데이터의 무결성을 지키기 위해, 
   데이터를 입력받을 때 실행되는 검사 규칙을 의미한다. 
   이러한 제약 조건은 CREATE 문으로 테이블을 생성할 때나 
   ALTER 문으로 컬럼을 추가할 때도 설정할 수 있다.

1. PRIMARY KEY(PK) - 유일키
   - 고유한 값
   - 각 행의 구분점으로 이용된다.
   - PRIMARY KEY는 테이블당 오직 하나의 필드에만 설정할 수 있다.
   - 이 제약 조건이 설정된 필드는 NULL값을 가질 수 없다.
   또한 중복값도 허용하지 않는다.

2. FOREIGN KEY(FK) - 외래 키
   - 외래키는 두 테이블을 서로 연결하는데 사용하는 키이다.
   - 중복이 가능하다.
   - 외래키가 포함된 테이블을 자식 테이블이라고 하고,
      외래키 값을 제공하는 테이블을 부모 테이블이라고 한다.
   - 회원, 주문, 상품 테이블이 있다면 회원 -> 상품 -> 주문 순서대로 만들고
      주문 테이블에서 누가 뭘 주문했는지 알아야하기 때문에 FK는 주문쪽에 있다.
   - 한명은 여러 개 주문을 할 수 있다. FK는 다쪽에 있다.

3. NOT NULL
   - NOT NULL 제약조건을 설정하면 해당 필드는 NULL 값을 저장할 수 없다.
   즉 이 제약조건이 설정된 필드는 무조건 데이터를 가지고 있어야 한다.

4. UNIQUE
   - UNIQUE 제약조건을 설정하면, 해당 필드는 서로 다른 값을 가져야 한다.
   즉 이 제약조건이 설정된 필드는 중복된 값을 저장할 수 없다.

5. DEFAULT
   - DEFAULT 제약 조건은 해당 필드의 기본 값을 설정할 수 있게 해준다.
   만약 레코드가 입력할 때 해당 필드 값을 전달하지 않으면 자동으로 설정된 기본 값을 저장한다.

DDL(Data Definition Language)
   - DDL 명령어란 데이터 정의어로써 테이블과 같은 데이터 구조를 정의하는 명령어로 
데이터 구조를 정의함에 있어서 발생할 수 있는 이슈로 생성, 변경, 삭제, 이름 변경의 명령어도 함께 포함하고 있다.
