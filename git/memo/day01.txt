**하나의 파일은 한명만 작업한다.

2. 브랜치를 만들어서 작업하자
3. 작업이 모두 끝나면 main으로 작업물을 합친다
4. 최종 브랜치는 main이다.

브랜치 명령어

1. 브랜치 생성
git checkout -b 브랜치명
	- 브랜치를 생성함과 동시에 만들어진 브랜치로 이동한다
git branch 브랜치명
	- 브랜치를 생성하는 명령어

2.브랜치 확인
git branch
	-만들어진 브랜치와 현재 나의 브랜치를 확인하는 명령어

3. 브랜치 삭제
git branch -D 브랜치명
	-브랜치를 삭제하는 명령어
4. 브랜치 수정(이름)
git branch -m [기존브랜치][수정할 브랜치]




5. 커밋 메세지 수정
git commit --amend
git commit --amend -m "새로운 커밋 메세지"
	-마지막에 commit한 메세지를 변경하는 명령어


git remote add 레포지토리명 깃허브주소
	-git-hub 주소를 레포지토리 명 주소에 담는명령어
	- origin : 개인 레포지토리
	-project : 팀 레포지토리

git remote remove 레포지토리명
	-저장된 remote의 레포지토리를 삭제하는 명령어

	
git push origin main
	- origin으로 main브랜치를 push하는 명령어
git pull project main
	- main 브랜치로 프로젝트의 파일을 pull받는 명령어

예외
	git push origin main
	git pull origin main

깃 커밋 규칙
   - *feat: 새로운 기능 추가
   - *fix: 버그 수정
   - docs: 문서 수정 (README 등)
   - style: 코드 포맷 변경 (세미콜론, 공백 등)
   - *refactor: 리팩토링 (기능 변화 없음)
   - test: 테스트 코드 추가/수정
   - chore: 빌드, 설정, 패키지, 기타 작업
   - perf: 성능 개선
   - ci: CI 설정 수정
   - build: 빌드 시스템 수정
   - *revert: 커밋 되돌리기
